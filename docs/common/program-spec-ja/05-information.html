05 資料の読込と情報検索

5.1 FAQとAI用資料の違い

情報源登録方法回答への利用
FAQ画面で質問・回答を入力、またはExcelから取込。登録した回答をそのまま返す。候補が複数ある場合はAIが選択を補助する。
AI用資料Word・Excel・PDFをアップロード。APIはTXTも受け付ける。本文を読み取り、文章を分割して関連部分を探し、AIが回答を作成する。

5.2 資料の取込

長い資料をそのままAIに渡さず、文章を区切って扱う。Embeddingにより、異なる言葉で質問されても意味の近い文章を探す。PostgreSQLには読み取った本文と、意味を表す数値の並びを保存する。

文章区切りごとにEmbeddingを順番に作成する。すべて成功してからDBへの書込みを始める。書込みに失敗した場合は今回の変更をすべて取り消し、資料だけが登録されて本文が不足する状態を防ぐ。一時ファイルは要求の終了時に削除する。

WordはMammothで本文を取得し、Excelはxlsxライブラリで表やセルを読み取る。PDFはページごとの文字を取得する。スキャン画像からの文字認識は行わない。スタッフが登録した内容は、管理者の承認後に回答へ使用する。

5.3 質問に合う情報の検索

1件のFAQに直接一致する場合はAIを呼ばずに回答を返す。適切なFAQが明確でなければ、キーワードとベクトルで候補を探し、Ollamaに選択を依頼する。FAQで回答できなければ資料を検索する。

質問されたサイトに属し、処理完了・承認済みの情報だけを使用する。却下されたExcelのFAQは、個別FAQの古い状態が残っていても検索や質問候補に使用しない。文脈を保つため、近くの文章区切りを補足する場合がある。

5.3.1 関連する本文を探す

キーワード検索とベクトル検索を組み合わせます。ベクトル検索では、質問とのCosine類似度が0.25を超える文章を候補にします。キーワードで見つかった文章も候補になります。関連する本文が見つからない場合は、質問の補足や問い合わせ先を案内します。

0.25は検索候補を絞るための値で、回答の正解率を表すものではありません。

5.3.2 AIで回答を作成する

質問・会話履歴・検索した本文をOllamaに渡します。AIには、提供した本文だけを使い、価格・数値・条件を推測しないよう指示します。会話履歴は質問の対象を理解するために使います。

BackendはAIが返したデータの形式と回答状態を確認し、回答を画面へ返します。情報不足、空の回答、AIのエラー時は案内メッセージを返します。

処理の流れ：関連本文を検索 → Ollamaが回答を作成 → Backendが形式・状態を確認 → 画面に表示。

5.4 見つからない場合・AIが処理中の場合

回答に必要な情報がない場合は、質問を詳しく入力するよう案内するか、問い合わせ先を表示します。Ollamaが処理中で新しい処理を受け付けられない場合は、少し待ってから再試行するよう案内します。自動で順番待ちや再送信は行いません。

同じ資料を再アップロードすると、重複して登録される場合があります。容量や処理の上限は第09章を参照してください。
