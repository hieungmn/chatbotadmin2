08 API仕様

Base pathは/api/v1です。下表のEndpointをこの後ろに付けます。Requestは送信データ、Responseはサーバーから返るデータです。

8.1 API一覧の見方

項目意味・例
MethodGET / POST / PUT / DELETE
Path parameterURL内の対象ID。例：/admin/faq/:idの:idにFAQのIDを指定。
QueryURLの?以降の検索条件。例：?site_id=s-wing。
Body（JSON）APIに送るJSONデータ。質問文や保存内容など。
Form-dataファイルと情報をまとめて送信。資料ファイルとsite_idなど。
JWT / Authorization管理APIを呼ぶとき、画面がログイン後のJWTをHTTP Headerに付けて送信します。
形式：Authorization: Bearer <token>。<token>は実際のJWTです。URLには入れません。
サイト権限スタッフ：権限があるサイトのみ。管理者：すべてのサイト。
HTTPステータスの確認
  • 401：ログインを確認できません。再度ログインしてください。
  • 403：ログイン済みですが、その操作の権限がありません。
  • 200：APIの処理が完了しました。チャットでは、回答の代わりに案内を返す場合もあります。回答できたかどうかはanswer_statusで確認します。

8.3 チャットの応答項目

項目意味
session_id会話ID。次の質問で同じIDを送る。
sourcefaq：FAQの回答。
ai：資料からAIが作成した回答。
escalated：問い合わせ先を案内。連絡先のリンクを表示し、質問を担当者へ自動送信しません。
fallback：代替メッセージ。
一部の短い応答では、この項目を省略します。
faq_idFAQ回答では実際のID。999はAI回答、-1は代替メッセージを表す特殊値で、実在するFAQのIDではない。
answer_statusanswered：回答済み。insufficient_context：根拠不足。provider_error：AI呼出し・応答処理のエラー。
is_fallbacktrue：通常の回答の代わりに、補足や問い合わせを案内。false：通常の回答。
batch_approval_statusExcelファイルの承認状態。却下されたファイルのFAQは編集・回答に使用できません。個別作成のFAQには値がありません。

8.4 APIに送るデータの例

チャットで質問を送る場合

次の例は、サイト「s-wing」のチャット画面からBackendに送信されるHTTPリクエストです。利用者はチャットに質問を入力するだけで、このコードを入力する必要はありません。

POST /api/v1/chat/query
Content-Type: application/json

{
  "site_id": "s-wing",
  "message": "バックアップについて教えてください"
}
  • POST /api/v1/chat/query：質問を送るAPI。
  • Content-Type: application/json：送信データの形式はJSON。
  • site_id：質問するサイトのID。message：利用者が入力した質問文。

Backendは質問に合う情報を探して結果を返し、画面が回答または案内を表示します。

資料をアップロードする場合

資料アップロードはPOST /api/v1/knowledge/uploadへForm-dataでfileとsite_idを送ります。HTTP 201は取込とDB保存の完了を示します。スタッフの資料は、その後に管理者の承認が必要です。
