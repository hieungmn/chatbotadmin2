10 運用とエラー対応

10.1 起動と更新

PostgreSQLとOllamaを起動し、各.envを設定してから、プロジェクトのルートで2つのTerminalを開きます。

# Terminal 1：Backend
cd chatbot-backend
npm run dev

# Terminal 2：Frontend
cd chatbot-frontend
npm run dev

FrontendのTerminalに表示されたURLを開きます。初回のDB作成では、PostgreSQLにpgvectorを導入し、空のDBにdatabase/schema.sqlを一度だけ実行します。既存DBの更新のために再実行しません。

対象Buildコマンド結果
Backendnpm run builddistを作成。npm startで実行。
管理画面（Frontend）npm run build:admindist-adminを作成。
チャット（Frontend）npm run buildBackendのpublic/staticへコピー。

停止はTerminalでCtrl+C。変更した部分を必要に応じてBuildし、再起動します。Backendは管理画面のHTMLを自動配信しません。ここではローカル実行を対象としています。

10.2 エラーと対応

状況HTTP / code対応・データへの影響
認証情報がない・無効401ログイン画面に戻り、再度ログインする。
サイトや管理操作の権限がない403管理者にサイト権限を確認する。操作による変更は行わない。
ファイルの容量超過413 / LIMIT_FILE_SIZE容量を小さくして再アップロード。
未対応の資料形式415 / UNSUPPORTED_KNOWLEDGE_FILE.docx / .xlsx / .xls / .txt / .pdfを使用。拡張子だけ変えても読めるとは限らない。
JSONの不正・容量超過400 / 413送信形式とサイズを確認。
資料のEmbedding作成・DB保存に失敗500OllamaとBackendログを確認して再アップロード。新しい資料を途中までDBに保存しない。
処理未完了の資料を承認409処理が完了した資料のみ利用。
送信頻度の超過429 / RATE_LIMITEDRetry-Afterに従って待つ。
AIの実行枠が満杯503 / SERVER_BUSY待って再実行。自動キューはない。
資料の根拠が不足・AIエラー200の場合もあるanswer_statusとis_fallbackを確認。補足・問い合わせの案内を表示。
却下中のFAQを編集・画像変更409 / FAQ_REJECTED所属するExcelファイル、または個別FAQを管理者が再承認する。

10.3 待ち時間を超えた場合

チャット：検索データ作成やFAQ選択の一段階で時間切れになっても、別の検索経路で回答できる場合があります。最後まで回答できない場合は、技術的な問題の案内と再試行・問い合わせを表示します。HTTP 200でも、is_fallback=true、answer_status=provider_errorになる場合があります。

資料の取込：1回のEmbedding作成が時間切れになると、その取込を終了します。「取込に失敗しました。Ollamaの稼働を確認し、もう一度アップロードしてください。」と表示し、HTTP 500を返します。新しい資料と本文はDBに保存されず、自動再試行はしません。

10.4 アップロード後に通信が切れた場合

サーバーが保存を完了した後、成功通知がブラウザに届く前に通信が切れることがあります。もう一度アップロードすると、同じ資料が別の1件として登録される場合があります。通信が戻ったら一覧を更新し、登録済みか確認してから再実行します。

10.5 バックアップと復元

バックアップ

  • pgAdminでDBをバックアップします。
  • uploads/faq-images、資料の原本、.envを別途保存します。
  • 自動バックアップ機能はありません。

復元手順

別のDBに復元 → 画像を元のフォルダーに戻す → .envを確認 → システムを起動 → 内容を確認して利用開始
