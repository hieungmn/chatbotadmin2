12 テストと動作確認

自動テストの実行方法と、ブラウザで確認する項目をまとめます。

12.1 自動テスト

Node.js 24以上を使用します。初回はBackend・Frontendの各フォルダーでnpm installを実行してください。テストにはNode.js標準のTest Runnerを使います。

DBとOllamaの応答をテスト用データに置き換えて確認します。実際のDBには保存せず、.envも読み込みません。Web・PostgreSQL・Ollamaを起動する必要はありません。bcryptとJWTは実際のライブラリで確認します。

テストする内容

テストファイル確認する内容
chatbot-backend/tests/auth.test.cjsログイン、パスワード照合、JWTの期限・変更後の無効化、アカウント停止、管理者・サイト権限。
chatbot-backend/tests/faq.test.cjs却下されたFAQの編集制限、ファイルと所属FAQの承認、保存失敗時のROLLBACK、Excelの重複・不完全な行のスキップ。
chatbot-backend/tests/knowledge-import.test.cjs本文・承認状態の保存、本文なし・Embedding失敗時に保存しないこと、DBエラー時に途中保存しないこと。
chatbot-backend/tests/ai.test.cjsRAGの回答データ形式、情報不足・AIエラー時の案内、同時実行数の制限、タイムアウト、処理の中止、不正なEmbedding。
chatbot-backend/tests/chat.test.cjs質問の入力制限、AI処理中の503、別サイトの会話の制限、切断時の中止。
chatbot-frontend/tests/widget.test.mjs回答・画像・リンクの表示用データ、案内メッセージでの評価ボタン制御、ログアウト時の認証情報削除。

Backendの全テストを実行

VS Codeでプロジェクトのルートフォルダーを開き、Terminalで実行します。

cd chatbot-backend
npm test

FAQのテストだけ実行

chatbot-backendフォルダーで実行します。他のファイルも同じ方法で指定できます。

node --test tests/faq.test.cjs

Frontendのテストを実行

プロジェクトのルートから別のTerminalを開いて実行します。

cd chatbot-frontend
npm test

結果の見方

  • pass：成功したテスト数。
  • fail：失敗したテスト数。実行が最後まで完了し、fail 0かつcancelled 0なら失敗・中止はありません。skippedは未実行の件数です。
  • 失敗した場合は、表示されたテスト名・ファイルの行番号・期待値と実際の値を確認します。

これらは処理ロジックの確認です。画面レイアウト、Reactの操作、実際のDBへの保存、実際のAI回答の正しさは別途確認します。

12.2 ブラウザでの動作確認

システムを起動し、下表の「操作・条件」を実行します。「期待する結果」と画面・API・DBの結果を比較してください。下表には自動テストの対象外も含みます。

確認する機能操作・条件期待する結果
ログイン正しいユーザー名とパスワードを送るJWTとアカウント情報を取得し、FAQ管理に移動する。password_hashは返さない。
未認証JWTなしで管理APIを呼ぶ401。変更されない。
権限権限のないサイトをスタッフが変更する403。対象データは変更されない。
スタッフのFAQ作成・変更・Excel取込を行う承認待ち。承認するまでは回答・候補に使わない。
管理者の下書き個別FAQを下書きとして保存するDBには残るが、回答・候補には使わない。承認後に利用できる。
Excel却下ファイルを却下し、所属FAQを編集する内容・画像の編集と個別承認を拒否する。409 / FAQ_REJECTED。
Excel再承認FAQ一括取込の編集で承認するファイルと所属FAQの状態が変わり、編集・回答利用が可能になる。
FAQ重複同じ質問・data_idを取り込む重複した行をスキップし、既存の回答を上書きしない。
FAQ画像6枚目、または上限を超える画像を送る拒否し、不要な新規ファイルを残さない。
資料の取込失敗OllamaのエラーやDB保存の失敗を起こす失敗を表示し、新しい資料や本文を途中までDBに保存しない。
サイト分離別サイトのsession_idで質問する別サイトの会話を使わせない。403。
FAQ回答一意に一致する公開FAQを質問する登録済み回答を表示。必要がなければAIで書き直さない。
AI回答FAQはないが承認資料に答えがある質問を送る関連本文を使って回答する。
根拠不足FAQにも資料にもないことを質問する補足または問い合わせを案内。answer_statusを確認する。
AI処理中実行枠が埋まった状態でAIを必要とする質問を送る503 / SERVER_BUSY。待ち行列に入れない。
評価ボタン役に立った／役に立たなかったを押す画面上だけで選択状態を変更し、評価をDBに記録しない。
