8. Giao diện API

Tiền tố chung: /api/v1. Bảng dưới ghi đường dẫn sau tiền tố, gồm 33 thao tác. “Quyền site” nghĩa là JWT hợp lệ và staff có quyền trên site đích; admin có toàn quyền. Mọi API quản trị có thể thêm 401/403 khi không đáp ứng xác thực/phân quyền.

JSON dùng Content-Type: application/json. Upload file/ảnh dùng multipart/form-data với boundary do HTTP client tạo. Không gửi bí mật cấu hình hoặc JWT trong URL. Các mã trạng thái trong bảng là nhánh controller tiêu biểu; lỗi middleware chung xem phần 10.

8.1 Hợp đồng upload tài liệu

POST /api/v1/knowledge/upload
Authorization: Bearer <token>
Content-Type: multipart/form-data; boundary=<do client tạo>

file: tài liệu Word/Excel/PDF (API cũng chấp nhận TXT)
site_id: s-wing

HTTP 201
{
  "success": true,
  "file_id": 123,
  "chunk_count": 8,
  "warnings": [],
  "message": "アップロードが完了しました。"
}

ID và số đoạn trên là dữ liệu minh họa. HTTP 201 chỉ trả sau khi xử lý và lưu xong; staff vẫn phải chờ duyệt để nội dung được dùng cho hỏi đáp.

8.2 Hợp đồng hỏi đáp

POST /api/v1/chat/query
{"site_id":"s-wing","message":"バックアップについて教えてください"}

HTTP 200 — ví dụ đáp án từ FAQ
{
  "success": true,
  "answer": "<nội dung FAQ đã đăng ký>",
  "redirect_url": null,
  "faq_id": 12,
  "is_fallback": false,
  "session_id": "sess_<UUID>",
  "source": "faq",
  "answer_status": "answered",
  "images": []
}
TrườngÝ nghĩa / phạm vi
session_idGửi lại ở câu hỏi tiếp theo của cùng hội thoại/site.
sourcefaq, ai, escalated hoặc fallback theo nhánh. Một số nhánh hướng dẫn ngắn không trả source; không coi trường này luôn hiện diện.
faq_idID thật của FAQ; nhánh AI thành công hiện dùng 999; hướng dẫn/fallback dùng -1. 999/-1 là giá trị báo nhánh, không phải ID của FAQ thật.
answer_statusanswered / insufficient_context / provider_error theo kết quả. response_kind=clarification xuất hiện ở nhánh yêu cầu làm rõ.
