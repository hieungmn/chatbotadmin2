トラブル対応・用語

トラブル対応

該当する状況を探し、再送信やデータ削除の前に確認してください。

対象：すべての利用者。起動の確認は運用担当者が行います。

ログインできない・ページを開けない

  1. 管理者から案内されたURLを確認します。
  2. ページを開けない場合は、運用担当者にFrontendとBackendの起動状態を確認してもらいます。
  3. ユーザー名やパスワードを確認します。改善しない場合は、管理者にアカウントの状態を確認してもらいます。

選択できるサイトがない

管理者に「ユーザー管理 → サイト権限」での設定を依頼してください。別のサイトへ一時的に保存しないでください。

FAQが回答に使われない

  1. 対象サイトを確認します。
  2. 承認済みで、下書きではないことを確認します。
  3. FAQに沿った具体的な質問で試します。更新直後は保存が完了してから試してください。

資料のアップロードに失敗

  1. ファイル形式と容量を確認します。PDFは文字を読み取れること、パスワードがないことが必要です。
  2. 処理中の案内が出た場合は、少し待って再試行します。
  3. 接続エラーの場合は、Ollama・PostgreSQL・Backendを確認してもらいます。
  4. 送信後に通信が切れた場合は、重複登録を避けるため、一覧を更新してから再送信してください。

区切り数はあるのに詳細画面でエラー

エラー画面の再試行を押します。運用担当者は、直近のコード・DB変更後にBackendを再起動したか確認してください。DBに本文が残っている場合があるので、すぐに削除・再アップロードしないでください。

回答に必要な情報がない

質問を具体的にしてください。コンテンツ担当者は、対象サイトのFAQ・資料が承認済みか、必要な内容があるか、「詳細を見る」で本文を読み取れているか確認します。

Ollamaに接続できない・待ち時間が長い

資料の情報不足とは別の処理エラーです。運用担当者はOllama、モデル、Backendのメッセージを確認します。利用者は後で再試行するか、問い合わせ先のリンクを利用してください。

AIの回答が誤っている

元の資料と照合し、価格・数値・条件・比較内容を確認します。古い情報や矛盾を修正し、質問文と誤った回答を担当者へ伝えてください。👎ボタンは画面の案内を変えるだけで、管理者へエラー報告を送信しません。

設置したサイトにチャットが表示されない

  1. コードを保存・公開したか、同じコードを複数設置していないか確認します。
  2. サイトIDが正しく、サイトが有効になっているか確認します。
  3. 同じPCで試す場合は、ウィジェットのBackend URLがhttp://localhost:3000になっているか確認します。
  4. Webサイト担当者に、ブラウザーのエラーや表示のブロックを確認してもらいます。

サポートへ伝える内容

画面名、対象サイト、直前の操作、エラー文、発生時刻を伝えます。画像を送る場合は個人情報を隠してください。パスワード、秘密の文字列、.env全体は送らないでください。

利用環境とセットアップ

状況対応方法
ページは開くがAPIがブロックされるFrontendの.envにVITE_API_URL=http://localhost:3000があること、Backendがポート3000で起動していること、画面をhttp://localhost:5173で開いていることを確認します。.env変更後は該当するサービスを再起動してください。
BackendがPostgreSQLへ接続できないサービス、ポート、DB_HOST・DB_PORT・DB_NAME・DB_USER・DB_PASSWORDを確認します。Webのログイン用パスワードとは別です。
SQLでvectorまたはvector.dllがないと表示される使用中のPostgreSQLに対応するpgvectorを、正しいフォルダーへ追加します。pg_available_extensionsも確認してください。pgAdminのフォルダーにはコピーしません。
PC再起動後にAIへ質問できないOllama、2つのモデル、実行アカウントを確認します。ollama listや/api/tagsで確認できます。FAQへの直接一致だけでは、AIが動作しているかは分かりません。
ログインできるがサイトがない管理者がスタッフへサイト権限を設定してください。スタッフのPCでソフトウェアを再インストールする必要はありません。
